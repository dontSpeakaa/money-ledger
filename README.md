# 我的账本

单人使用的个人理财 Web 应用。主页是一个对话框：跟 AI 说「午饭 38」，
它自己挑分类、记到账本里，还能回答「今天花了多少」。账户也由 AI 配置。
可以添加到 iPhone 主屏幕，像原生 App 一样打开。

零外部依赖，只用 Node.js 内置模块（`node:http`、`node:sqlite`、`node:crypto`）。
数据存在本机的一个 SQLite 文件里，不上传任何服务器。
AI 接口用的是你自己填的地址（OpenAI / DeepSeek / 通义千问 / 自建中转都行），
Key 存在本机，不经过任何第三方服务。

## 快速开始

```bash
npm start          # 启动，默认 http://localhost:12000
```

首次打开网页会引导你设置用户名和密码。之后所有数据都属于这一个账号。

想先看看界面长什么样，可以写入演示数据：

```bash
npm run seed-demo  # 6 个账户 + 最近 3 个月的示例交易，账号 me / demo123456
npm start
```

演示数据会清空已有账户和交易，只在空库上使用。想彻底清空重来，用 `npm run reset`。

## 在 iPhone 上打开

### 方式一：局域网直连（推荐，数据不出家门）

1. 确保手机和跑服务的电脑连同一个 Wi-Fi。
2. 查电脑的局域网 IP：macOS/Linux 用 `hostname -I` 或 `ipconfig getifaddr en0`，Windows 用 `ipconfig`。
3. 服务默认监听 `0.0.0.0:12000`，直接用 Safari 打开 `http://<局域网IP>:12000`。

会话 Cookie 会按实际协议决定是否加 `Secure`：走 http 时自动不加，否则 Safari 会拒收 Cookie、登录后立刻掉线。

### 方式二：公网地址

如果服务跑在云主机或有域名，直接访问 `https://<你的域名>`。HTTPS 下 Cookie 自动带 `Secure`。
建议放在 Nginx/Caddy 后面并配好 TLS，反代记得传 `X-Forwarded-Proto: https`。

### 方式三：纯手机本地模式（GitHub Pages，不需要电脑常开）

不想一直开着电脑，就把前端传到 GitHub Pages，数据直接存在 iPhone 的浏览器里。
一条命令搞定（需要一个有 `repo` 权限的令牌）：

```bash
GITHUB_TOKEN=ghp_xxx ./scripts/deploy-pages.sh money-ledger
```

脚本会创建仓库、推送 `main`、并把 Pages 指向 `/docs` 目录，完成后得到
`https://<用户名>.github.io/<仓库名>/`，用 Safari 打开后按上面的步骤「添加到主屏幕」即可。
想手动做也行：`npm run build:static` 生成 `docs/`，推到仓库后在 Settings → Pages 里
选该分支的 `/docs` 目录发布。

这个模式的特点：

- **没有服务器**，业务逻辑跑在浏览器里，数据存 IndexedDB，只有这台手机能看到。
- 完全离线可用（Service Worker 缓存了整个 App），装好后断网也能记账。
- 因为没有服务器，也就没有跨设备同步。换手机或清理浏览器数据前，
  务必用「设置 → 导出完整备份」，再从备份恢复。
- 想清空重来，用「设置 → 清空全部数据」。

也可以给服务器模式临时加 `?local=1` 走本地模式，方便对比两种模式的表现。

### 添加到主屏幕（变成本地 App）

1. Safari 打开上面的地址，先登录一次。
2. 点底部中间的「分享」按钮（方框加向上箭头）。
3. 在列表里向下找到「添加到主屏幕」，改个名字，点「添加」。
4. 从主屏幕图标打开，就是全屏无地址栏的独立 App。

注意：必须是 **Safari**。Chrome、微信内置浏览器都加不了主屏幕，也不会全屏运行。
另外 PWA 的「独立运行」和 Service Worker 离线缓存只在 HTTPS（或 `localhost`）下生效。
走局域网 http 时能正常使用和加到主屏幕，但离线缓存不启用。

## 需要联网吗

**记账本身不需要。** 这个应用没有任何前端外部依赖：没有 CDN、没有第三方脚本、
没有外部字体（用的是 iOS 系统字体），也没有 npm 依赖，不需要 `npm install`。

唯一会主动联网的地方是 AI 对话：请求发给你在「设置 → AI 接口」里填的那个地址
（服务器模式下由服务端转发，Key 不出服务端；纯手机模式下由浏览器直连）。
不填 AI 接口也能用，只是没有对话记账，其余页面照常看数据。

除此之外它需要的只是「手机能连到跑服务的那台电脑」：

| 场景 | 是否需要互联网 |
| --- | --- |
| 电脑和手机在同一 Wi-Fi | 不需要，走局域网即可 |
| 在外网访问家里的电脑 | 需要内网穿透（Tailscale / Cloudflare Tunnel）或端口转发 |
| 服务跑在云主机 | 需要 |

所以如果电脑放在家里常开，数据全在本机的 SQLite 文件里，断网也不会丢；
只有 AI 对话那一下需要连上你填的服务商。

Service Worker 的离线缓存只在 HTTPS 或 `localhost` 下生效；局域网 http 访问时不启用，
但那时你本来就连着服务器，不影响使用。

## 功能

- 对话：主页就是对话框，说一句话就记账，也能问「今天花了多少」
- 总览：净资产、本月收支、账户余额、支出构成、近 6 个月趋势、分类排行
- 明细：按月查看流水，支持搜索、按账户和分类筛选，点一条可以改或删
- 账户：全部由 AI 配置（建卡、校准余额、改名、隐藏、删除），没有手动添加入口
- 预算：给分类设置月度上限，超支有提醒
- 导入：支付宝 / 微信 / 银行导出的 CSV，自动识别列名；也支持 JSON。重复记录自动跳过
- 导出：CSV 和 JSON 备份，随时把数据带走

## AI 记账助手（主页对话）

1. 设置页 → 「AI 接口」→ 选一个预设（OpenAI / DeepSeek / 通义千问 / Moonshot / 智谱）
   或直接填自己的中转地址，再填模型名和 API Key。
2. 点「测试连接」确认能通，然后回「对话」页。
3. 直接说人话：

```
午饭 38
地铁 6 块，奶茶 18
我有一张招行卡，余额 12000
把信用卡余额改成 -1500
今天花了多少？
这个月餐饮花了多少？
```

AI 会自己挑分类（餐饮 / 交通 / 购物…）、选账户、写备注，记完在对话里回一张小票，
同时账本、总览、明细立刻更新。说错了就直接说「把刚才那笔删掉」或到明细里点掉。

实现上：前端把工具定义（记账 / 查账 / 建账户 / 校准余额 / 转账 / 删除）交给模型，
模型要调工具就返回 `tool_calls`，前端执行后把结果喂回去，直到它给出最终回复。
工具最终都调已有的 `/api/*` 接口，所以服务器模式和纯手机模式行为一致。

| 接口 | 说明 |
| --- | --- |
| `GET /api/ai/config` | 读取配置，只返回 `base_url` / `model` / `has_key` / `ready` |
| `POST /api/ai/config` | 保存配置；`api_key` 留空表示不修改，`clear_key: true` 清空 |
| `POST /api/ai/chat` | 转发 `messages` + `tools` 给服务商，原样返回它的 JSON |

服务器模式下 API Key 只存在服务端的 SQLite 里，浏览器永远拿不到；
纯手机模式下 Key 存在本机 IndexedDB，浏览器直连服务商（要求服务商允许跨域）。

## 消费时自动记账（iPhone 快捷指令）

生成一个长期令牌后，任何消费都能用一条链接记账，不必打开网页。

1. 设置页 → 「自动化（iPhone 快捷指令）」→ 生成令牌
2. 复制页面给出的示例，在「快捷指令」里用「获取 URL 内容」调用：

```
POST http://<服务器IP>:12000/api/quick?token=<令牌>
{"amount":38.5,"category":"餐饮","note":"午饭"}
```

也可以直接用 GET，方便做成小组件或 Siri 短语：

```
http://<服务器IP>:12000/api/quick?token=<令牌>&amount=38.5&category=餐饮&note=午饭
```

金额传正数默认记为支出。令牌等价于密码，只放在自己的设备上；不用了可以在设置页撤销。

## 配置

| 环境变量 | 说明 | 默认 |
| --- | --- | --- |
| `PORT` | 监听端口 | `12000` |
| `HOST` | 监听地址，默认允许局域网访问 | `0.0.0.0` |
| `MONEY_DB` | SQLite 文件路径 | `data/money.db` |
| `MONEY_INSECURE_COOKIE` | 设为 `1` 时强制不加 Secure Cookie（正常情况无需设置，程序会自动判断 http/https） | 自动判断 |

## 开发

```bash
npm test           # 冒烟（47 项）+ 本地模式（75 项）+ AI 助手（70 项）+ 合同一致性（32 项）
npm run make-icons # 由 icon.svg 重新生成各尺寸 PNG 图标
```

代码结构：

```
server/db.js      SQLite 表结构与查询
server/auth.js    密码哈希、会话、API 令牌
server/index.js   HTTP 服务、全部接口、AI 请求转发
public/app.js     前端逻辑（原生 JS，无构建步骤）
public/ai-tools.js AI 工具定义 + 执行（纯逻辑，前端和测试共用同一份）
public/local-api.js 纯手机模式的后端实现
scripts/          演示数据、图标生成、冒烟测试、AI 测试
```

## 数据安全

- 密码用 scrypt 加盐哈希，登录靠 HttpOnly 会话 Cookie
- 生产使用请放在 HTTPS 后面（Cookie 默认带 `Secure`），或只在内网访问
- 备份就是把 `data/money.db` 复制走，或者用设置页的导出功能
